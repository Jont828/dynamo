Portable DGD conventions
------------------------
- Use `apiVersion: nvidia.com/v1beta1` and `kind: DynamoGraphDeployment`.
- Set `spec.backendFramework` to `sglang`, `vllm`, or `trtllm` where applicable.
- Use the existing backend template style in:
  - `examples/backends/sglang/deploy/agg.yaml`
  - `examples/backends/vllm/deploy/agg.yaml`
  - `examples/backends/trtllm/deploy/agg.yaml`
- Use image placeholders consistent with neighboring examples, such as:
  - `my-registry/sglang-runtime:my-tag`
  - `my-registry/vllm-runtime:my-tag`
  - `my-registry/trtllm-runtime:my-tag`
- Keep frontend and worker runtime versions aligned.
- Do not copy cluster-specific values from a private deployment:
  - no AKS `agentpool` selectors
  - no H100/B200-only affinity in a generic one-GPU example
  - no private PVC names, Lustre subpaths, namespaces, registries, or pull secrets
- Reference `hf-token-secret` where model access may require it, consistent with neighboring examples.
- Request both GPU limits and requests when adding a GPU worker.
- Use a reasonable `sharedMemorySize` for diffusion workers.
- Keep optional model-cache PVC/preload jobs out of the minimal DGD, or document them as optional rather than required.

Generated-media storage
-----------------------
Local launchers commonly use `file:///tmp/dynamo_media`, but worker-local files are not externally retrievable from a Kubernetes client.

For portable examples:
- Mount a size-limited `emptyDir` at `/tmp/dynamo_media` (20Gi for images/audio, larger for video is reasonable).
- Use `response_format=b64_json` in smoke-test examples.
- Explain that URL responses require object storage such as S3 plus `--media-output-http-url`.
- A shared PVC by itself does not make returned files publicly accessible.
- Avoid implying that worker-local `file://` URLs work outside the Pod.

FLUX.1-schnell details to verify
--------------------------------
The known working cluster-specific deployment was named `flux-1-schnell-sglang-agg-h100`; the portable example should remove H100/AKS/PVC-specific configuration and use `flux-1-schnell-sglang-agg`.

The cluster deployment used:
- one H100 80 GB GPU
- SGLang `--image-diffusion-worker`
- a preloaded shared Hugging Face cache
- `response_format=b64_json`
- four inference steps

Do not add `--enable-torch-compile` without testing it. A previously tested Dynamo/SGLang version absorbed the same-named flag in the LLM argument parser rather than forwarding it to the diffusion configuration.

Also inspect these two runtime correctness details before documenting canonical Schnell request parameters:

1. `components/src/dynamo/sglang/request_handlers/image_diffusion/image_diffusion_handler.py` has used logic equivalent to:
   `guidance_scale = nvext.guidance_scale or DEFAULT_GUIDANCE_SCALE`
   This prevents an explicit Schnell value of `0.0` from being honored. If still present, fix it using an explicit `is not None` check and add a unit test, or avoid claiming that `guidance_scale: 0.0` works.

2. `components/src/dynamo/sglang/health_check.py` has placed image diffusion `num_inference_steps` and `guidance_scale` at the top level even though the handler reads them from `nvext`. On runtime 1.5+, worker canary health checks are enabled and have a short timeout; a nominal one-step health check can therefore fall back to 50 steps. If still present, nest the fields under `nvext` and add/update a focused unit test. Keep any runtime fixes focused and separate from unrelated refactoring.

Validation
----------
At minimum:

1. Parse every new YAML document with PyYAML.
2. Validate each DGD against the `v1beta1` OpenAPI schema in:
   `deploy/operator/config/crd/bases/nvidia.com_dynamographdeployments.yaml`
   Using Python `jsonschema` is sufficient if kubeconform is unavailable.
3. Run:
   `git diff --check`
4. Run the docs lint on the relevant docs tree/files. The standard command is:
   `python3 docs/fern/scripts/docs_lint.py --scan docs`
   If the checkout has unrelated local docs files, distinguish those baseline failures from new failures.
5. Run:
   `python3 docs/fern/pages/recipes/_catalog/validate.py`
6. Run from `docs/fern/`:
   `fern check`
   `fern docs broken-links`
   Generated Python/Rust API pages may need to be generated first on a clean checkout; do not “fix” unrelated missing generated files in this PR.
7. Confirm every scoped launcher maps to an existing DGD and that the FastVideo mapping remains existing rather than duplicated.
8. If runtime fixes are made for SGLang guidance or health checks, run the focused SGLang unit tests and add regression coverage.

Review checklist
----------------
- Every new file has the correct 2025-2026 SPDX header form.
- No cluster names, node-pool names, private PVCs, registries, workload details, or credentials are committed.
- Commands and model names match the corresponding launch scripts as they exist on the branch being changed.
- Media URL limitations are explicit.
- The ordinary GLM-Image DGD does not accidentally use process-local SHM across Pods.
- The cross-node GLM-Image DGD actually forces AR and DiT onto different nodes.
- The LoRA DGD initializes the Dynamo LoRA manager, not only the underlying vLLM `--enable-lora` flag.
- New manifests are embedded or linked from the docs site rather than left discoverable only through GitHub browsing.
- Avoid unrelated formatting or generated-file churn.
