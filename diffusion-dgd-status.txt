FLUX example
------------
The portable SGLang FLUX manifest is:
- examples/backends/sglang/deploy/agg_image_diffusion.yaml
- DGD name: flux-1-schnell-sglang-agg
- Model: black-forest-labs/FLUX.1-schnell

It was generalized from the known-working cluster deployment and excludes its
AKS node-pool selectors, private Lustre PVC, namespace, and model-preload job.
It uses one GPU and worker-local, size-limited media storage. Clients should
request response_format=b64_json unless external object storage and a public
media HTTP URL are configured.

Outstanding validation and review
---------------------------------
- No new DGD has been deployed to Kubernetes or smoke-tested on a GPU cluster.
- The GLM-Image multi-Pod/NIXL manifests need deployment validation, including
  stage discovery, connector setup, and cross-node anti-affinity.
- The vLLM-Omni LoRA manifest needs an end-to-end load/generate/unload test.
- Model memory requirements and one-GPU assumptions should be reconfirmed on
  current main and the selected runtime images.
- Full `fern check` is blocked in this checkout by missing generated Python and
  Rust API pages that are unrelated to these changes.
- Full docs lint reports unrelated pre-existing/untracked docs files without
  SPDX headers; those files must not be swept into this change.
- `fern docs broken-links` has not been completed.

Known runtime concerns to investigate
-------------------------------------
1. SGLang image diffusion currently uses a truthiness fallback for
   nvext.guidance_scale. An explicit FLUX.1-schnell guidance scale of 0.0 may
   be replaced by the default 7.5. This should use an explicit None check and
   have regression coverage if fixed in this work.
2. The SGLang image-diffusion health payload places num_inference_steps and
   guidance_scale at the top level even though the handler reads them from
   nvext. On runtime 1.5+, canary checks may therefore run the 50-step default
   instead of the intended one-step request.
3. The local GLM-Image disaggregated launcher uses process-local shared memory.
   The Kubernetes DGD intentionally uses the repository NIXL stage config
   because separate Pods cannot share that connector.

Scope exclusions
----------------
No new diffusion DGD was created for realtime audio/transcription scripts,
validation helpers, or examples/common/launch_utils.sh. Those are not distinct
diffusion deployments.
